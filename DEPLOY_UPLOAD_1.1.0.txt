PatientFiles 1.1.0 — тест функции «Прикрепить файл»
===================================================

ВАЖНО
-----
Это тестовая версия. Сначала используйте тестового пациента/МКАБ.
Рабочий web.config из текущего сервера НЕ заменяйте файлом web.config.example.

Что добавлено
------------
1. Кнопка «Прикрепить файл».
2. Выбор файла, вида документа, даты и необязательного описания.
3. Файл сохраняется в UploadRoot под именем <uuid>.<extension>.
4. Затем в одной SQL-транзакции создаются:
   - dbo.atf_FileInfo
   - dbo.atf_FileAttachment
5. atf_FileInfo.DescGuid = hlt_MKAB.UGUID текущего MKABID.
6. atf_FileAttachment.Path = полный путь к сохранённому файлу.
7. Если SQL-запись не удалась, сохранённый файл удаляется.

Настройка рабочего web.config
-----------------------------
Добавьте ОТДЕЛЬНУЮ строку подключения MisWriteDb. Не выдавайте INSERT
существующему read-only пользователю MisDb, если можно этого избежать.

Пример с заглушками смотрите в web.config.example.

В appSettings добавьте:

  <add key="UploadRoot" value="\\FILE_SERVER\SHARE_ROOT" />
  <add key="MaxUploadSizeMb" value="30" />
  <add key="UploadCreateUserId" value="1" />
  <add key="UploadCreateUserName" value="Веб-модуль" />

UploadRoot обязательно должен входить в AllowedRoots.

SQL-права MisWriteDb
--------------------
SELECT: dbo.hlt_MKAB, dbo.atf_FileType
INSERT: dbo.atf_FileInfo, dbo.atf_FileAttachment

См. Sql\03_permissions_example.sql.

SMB-права
---------
Identity Application Pool должна иметь не только чтение, но и создание,
запись, переименование и удаление файлов в UploadRoot.

Перед первым тестом
-------------------
1. Через штатную десктопную МИС прикрепите тестовый файл к тестовой карте.
2. Выполните Sql\04_verify_attachment_convention.sql для этой карты.
3. Сверьте фактическое имя файла и GUID-поля.

Почему это важно: в присланном проекте tmmis_find_and_attach основная логика
прикрепления скрыта в LocalFileToMkabAttachOperator. Исходника этого оператора
в архиве нет. Из DAG подтверждены UGUID пациента, тип файла и автор записи,
но точный код создания имени/INSERT находится именно в отсутствующем операторе.

Текущая реализация использует безопасную схему:
- имя физического файла = новый UUID + исходное расширение;
- Guid записей atf_FileInfo/atf_FileAttachment создаёт сама БД штатными default;
- остальные служебные поля также оставлены штатным default МИС.

После успешного теста
---------------------
Проверьте:
- файл появился в UploadRoot;
- Path в atf_FileAttachment точно указывает на него;
- rf_FileInfoID ведёт в созданный atf_FileInfo;
- DescGuid созданного atf_FileInfo равен UGUID пациента;
- документ открывается и в веб-модуле, и в десктопной МИС;
- в App_Data\Logs есть запись UPLOAD.
